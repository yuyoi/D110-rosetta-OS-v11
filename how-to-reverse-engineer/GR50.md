# Roland GR-50 (guitar synthesizer): starting point

**Nothing here is verified yet.** This file lists what to find out, in order, so a session does not guess.

## What we think (hypothesis, check each)
- The GR-50 has an LA-family sound engine with PCM, related to the D-10 / D-110 generation (the user plans to test
  a PN-D10-01 card in it, which suggests the same card format).
- On top it has a guitar pitch-to-MIDI section (GK pickup input, per-string pitch detection). That part may run on
  its own processor.

## First questions (answer from the service notes, the board and MAME)
1. Which CPU(s)? Part numbers on the board. If it is an MCS-96 (8096/8097/8098) our tools work as is.
2. Is there a MAME driver? Search the MAME source for "gr50" / "GR-50" and read its memory map.
3. Which chips hold the OS (EPROM or mask ROM, socketed or soldered)? Control/tone ROM? PCM ROMs?
4. Is the sound part the same LA32 (MB87136) as the D-110?
5. Display, buttons, card slot.

## Then
- If the CPU and memory map match the D-10 family: follow `PORT_D10.md` (same steps, new map file `GR50_MAP.md`).
- If it is a different CPU: the disassembler, assembler and simulator need a new decoder for that CPU. Start with
  the decoder (checked against MAME's disassembler like `test_mcs96_dis.py` does), then the flow tracer.
- Guitar-specific ideas only make sense after the pitch-to-MIDI path is traced (per-string channels, trigger timing).

## Keep track
Create `GR50_MAP.md` with: dump hashes, CPU, memory map, vectors, then findings with status words, like
`IC19_MAP.md`.
